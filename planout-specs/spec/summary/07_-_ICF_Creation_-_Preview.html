1.  Frontend
1.1Overview

The ICF Preview feature provides a final "read-only" view of the Informed Consent Form (ICF) before it is officially published. It allows users to review the document layout and content in a simulated PDF format, ensuring everything is accurate before finalizing the document.

1.2Step-by-Step Flow
1.Loading: When the user opens the preview page, the system automatically retrieves the document details and all associated content sections.
2.Review: The document is displayed in a simulated PDF view, allowing the user to read the full text and verify the structure.
3.Adjustment: Users can use the toolbar to zoom in or out to better inspect specific parts of the document.
4.Navigation: If the user identifies any errors, they can click the "Back to Review" button to return to the previous editing stage.
5.Publishing: Once the user is satisfied, they click the "Publish" button. Upon success, the button is replaced by a confirmation badge, indicating the document is now finalized.
1.3Key Concepts
–Simulated PDF View: A visual representation of the final document that mimics how the ICF will appear once generated, allowing for a final quality check.
–Document Toolbar: A control area that displays the document title and page count, while providing zoom tools for better readability.
–Publishing: The final action that locks the document content and officially issues the ICF.
–Back to Review: A safety mechanism that allows users to exit the preview and return to the editing phase if they spot mistakes.
1.4Business Value

This feature acts as a final quality assurance gate. By providing a clear, accurate preview of the document, it reduces the risk of errors in legal or clinical documentation. It empowers users to confidently finalize their work, knowing exactly what the end result will look like before it is officially published.

2.  Logic
2.1Overview

The ICF Preview and Publication feature allows users to review a document in a simulated PDF format before finalizing it. This ensures that the document content and layout are correct before it is officially released. Once the user is satisfied with the preview, they can trigger the publication process to lock the document and mark it as complete.

2.2Step-by-Step Flow
1.Loading the Preview: When you navigate to the preview screen, the system automatically gathers the document’s details (such as the title and status) and all its individual content sections.
2.Reviewing the Document: The gathered information is displayed in a simulated PDF view, allowing you to verify the document's appearance and content.
3.Initiating Publication: Once you have confirmed the document is ready and all necessary approvals are in place, you click the "Publish" button.
4.Finalizing: The system processes the request to lock the document. Upon success, the interface updates to display a "ICF Published Successfully" badge, confirming the document is now officially published with a recorded timestamp.
2.3Key Concepts
–Metadata: The high-level information about your document, such as its title, current status, and creation date.
–Sections: The individual blocks of content that make up the full document, which are assembled together for the preview.
–Publication: The final step in the document lifecycle that locks the content, preventing further edits and marking the document as officially released.
–Approval Gates: Pre-defined checks that must be satisfied before the system allows you to publish the document, ensuring compliance and quality control.
2.4Business Value

This feature provides a "what-you-see-is-what-you-get" experience, reducing errors by allowing stakeholders to perform a final quality check before a document is made official. By automating the publication process and providing clear status updates, the system ensures that document records are accurate, timestamped, and protected from unauthorized changes after they have been finalized.
