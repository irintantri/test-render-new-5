1.1Overview

The Wrapper Shell is a consistent structural container designed for the BeOne POC creation flow. It acts as a "frame" that surrounds every page in the five-step process, ensuring that users always have access to the same navigation tools, status indicators, and project metadata regardless of which step they are currently viewing.

1.2Step-by-Step Flow
1.Initialization: When a user navigates to a page within the creation flow, the system identifies the current step and any available project details (such as the Protocol ID, ICF name, and version).
2.Navigation Display: The shell renders a breadcrumb bar at the top, allowing the user to easily return to the main Dashboard or identify their current location within the "Consent Creation" process.
3.Metadata Injection: The system checks which project details are available. If data exists, it displays the Protocol ID, ICF name, and version as visual "pills" or labels to provide immediate context.
4.Progress Tracking: A step indicator is displayed to show the user exactly where they are in the five-step sequence.
5.Content Rendering: The specific page content for the current step is injected into the center of the shell, ensuring the surrounding navigation and metadata remain fixed and visible.
1.3Key Concepts
–Wrapper Shell: A standardized layout template that ensures a consistent look and feel across different parts of the application.
–Breadcrumbs: A navigation aid that shows the user's path, allowing them to jump back to previous levels like the Dashboard.
–Conditional Metadata: Information (like Protocol ID or version) that only appears on the screen if that specific data has been provided, keeping the interface clean.
–Step Indicator: A visual progress bar that helps the user understand how much of the five-step creation process they have completed.
1.4Business Value
–Improved User Experience: By providing a consistent layout, users don't have to re-orient themselves when moving between steps, reducing confusion and errors.
–Context Awareness: Displaying key project identifiers (like Protocol ID and version) directly in the header ensures that users always know exactly which project they are working on without needing to navigate away.
–Efficiency: The standardized progress indicator helps users track their work, leading to a more predictable and efficient completion of the consent creation process.
