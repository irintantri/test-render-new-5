1.  components
1.1Overview

The "Edit and Refine" page features a persistent navigation bar at the bottom of the screen. This bar provides users with clear, accessible options to either return to the previous configuration stage or finalize their work by submitting the document for formal review.

1.2Step-by-Step Flow
1.Navigation Options: The user is presented with two primary actions: "Back to Setup" and "Submit for Review."
2.Returning to Setup: If the user selects "Back to Setup," the system immediately navigates them back to the initial configuration page for the current protocol.
3.Submitting for Review: If the user selects "Submit for Review," the system initiates a request to update the document's status from "Draft" to "In Review."
4.Processing State: While the submission is being processed, the "Submit for Review" button is temporarily disabled to prevent duplicate requests.
5.Completion: Upon a successful submission, the system automatically redirects the user to the review page for that specific document.
1.3Key Concepts
–Persistent Action Bar: A fixed navigation area at the bottom of the screen that ensures essential controls are always available to the user, regardless of how much content is on the page.
–Document Status Transition: The automated process of moving a document from a "Draft" state to an "In Review" state, signaling that the user has finished their edits.
–Submission Guard: A safety feature that disables the submit button during processing to ensure data integrity and prevent accidental multiple submissions.
1.4Business Value

This feature streamlines the user workflow by providing a clear path to completion. By placing navigation and submission controls in a consistent, easy-to-reach location, we reduce user effort and minimize the risk of errors. The automated status transition ensures that the document lifecycle is managed accurately, allowing for a seamless handoff from the editing phase to the review phase.

2.  logic
2.1Overview

The "Submit for Review" feature allows users to finalize their work on the "Edit and Refine" page. By clicking this button, the user signals that the document is ready for the next stage of the workflow, moving it from a draft state into an official review process.

2.2Step-by-Step Flow
1.Initiation: The user clicks the "Submit for Review" button located in the bottom action bar.
2.Verification: The system checks to ensure the document exists and is valid for submission.
3.Status Update: The system automatically updates the document's status from "Draft" to "In Review" and records the time of the update.
4.Confirmation: The system confirms the update and prepares the document for the next phase of the workflow.
2.3Key Concepts
–Document Status: A label that tracks where a document is in its lifecycle (e.g., moving from a working draft to a formal review).
–In Review: The specific status assigned to a document once the user has finished editing and submitted it for approval.
–Workflow Transition: The automated process of moving a document from one stage to another, ensuring the system always reflects the current state of the work.
2.4Business Value

This feature streamlines the transition between editing and approval, reducing manual administrative work. By automating the status change, it ensures that stakeholders are immediately notified that a document is ready for review, which helps maintain project momentum and ensures that documents move through the pipeline efficiently without unnecessary delays.

3.  Data
3.1Overview

The "Edit and Refine" page features a bottom action bar designed to help users manage their documents efficiently. This interface provides two primary functions: saving ongoing work as a draft and submitting a completed document for formal approval. The system ensures that documents move through a controlled workflow, preventing accidental submissions and maintaining clear status tracking.

3.2Step-by-Step Flow
1.Saving Progress: When a user makes changes to a document, they can save their work. The system updates the document content and metadata while keeping the document in its current state.
2.Initiating Submission: When the user is ready to finalize their work, they trigger the submission action from the bottom bar.
3.Status Verification: The system automatically checks the document’s current status. It will only proceed if the document is currently marked as a "Draft."
4.Finalizing Submission: If the document is a valid draft, the system updates its status to "In Review," signaling that it is ready for the next stage of the process. If the document is not in a draft state, the system will prevent the submission to avoid errors.
3.3Key Concepts
–Draft: The initial state of a document where the user is actively editing content.
–In Review: The status assigned to a document once it has been submitted, indicating it is no longer editable by the author and is awaiting further action.
–Status Transition: The controlled movement of a document from one stage (Draft) to another (In Review) to ensure data integrity.
–Metadata: Additional descriptive information attached to the document that is saved alongside the content during updates.
3.4Business Value
–Data Integrity: By enforcing status checks, the system prevents users from accidentally submitting documents that are not ready or are already in the review process.
–Workflow Efficiency: The bottom action bar provides a clear, consistent user experience, allowing authors to easily toggle between saving their progress and moving their work forward.
–Audit Readiness: Every update and status change is tracked with a timestamp, ensuring there is a clear record of when a document was modified or submitted for review.
